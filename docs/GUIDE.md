# Pendulum · full guide

*([back to the README](../README.md))*

**Shape the personality of an LLM without guessing which token to change on which layer.**

Pendulum reads the inner *workspace* of a GGUF model through Anthropic's [Jacobian lens](https://transformer-circuits.pub/2026/workspace/index.html). It draws a personality profile (10 axes plus custom levers), finds where each trait lives across the layers, then offers calibrated levers you push with the mouse. The result exports as a llama.cpp *control vector*, or straight into a copy of the GGUF for the architectures that allow it.

## Launch
Python 3.11 or newer (tested with 3.13), an NVIDIA GPU preferably.

1. PyTorch with CUDA, depending on your system: see [pytorch.org](https://pytorch.org/get-started/locally/) (on Windows, for example `pip install torch --index-url https://download.pytorch.org/whl/cu130`).
2. The rest: `pip install -r requirements.txt` (including `jlens`, the Jacobian lens, installed from GitHub; it is only used to train a lens).
3. llama.cpp: on first launch, the assistant looks for it (the configured folder, `PENDULUM_LLAMA`, `D:/llama.cpp`, `C:/llama.cpp`, the PATH, build layouts such as `build/bin/Release` included) and otherwise offers the build that suits the machine (CUDA not newer than the driver, else Vulkan or CPU; every other build stays available), downloaded with its sources and checked by sha256 into `llama.cpp/` of the working folder. By hand: a [release](https://github.com/ggml-org/llama.cpp/releases) for your system (`llama` and `ggml` libraries, `llama-fit-params`, `llama-server`); to convert safetensors models, the repository as well (`gguf-py`, `convert_hf_to_gguf.py`). The folder is set in ⚙ → ENGINE.
4. `python Pendulum.pyw` (on Windows, `pythonw Pendulum.pyw` avoids the console; on Linux it should run with a llama.cpp build made with `-DBUILD_SHARED_LIBS=ON`, untested so far: see also Docker below). On first launch (no `settings.json` in the working folder), the **SETUP** assistant goes through four screens: working folder, llama.cpp, model folders (the Hugging Face cache only, or a folder of your own as well), judge (optional); SKIP SETUP keeps the defaults, ⚙ → SETUP… reopens it. Options: `--data-dir FOLDER` (working folder for this run), `--load model.gguf`, `--ctx N`, `--lever warmth=-1,humor=0.8`, `--chat "…"`, `--help` for the rest.

Icon: `python ui/icon.py` writes into `assets/` (ignored by git) the Windows icons (`pendulum_nerv.ico`, `pendulum_unit01.ico`), a 256×256 PNG and Stream Deck PNGs on black (with or without the PENDULUM title), for a shortcut of your own. In the app, the window and taskbar icon follows the accent color.

## Usage
1. **MODELS** (Ctrl+M): a separate window (large list on the left, details on the right) to pick a GGUF or a safetensors model (`+ FOLDER` to add a folder). The placement plan is shown per GPU (model, KV, compute, lens); it is computed in the background for every model. The **LOAD OPTIONS** (split, main GPU, flash attention, KV cache; for this model only or for all) sit right below, and the plan is recomputed on every change. A solid orange dot = lens available locally, a ring = on the Hub (downloaded at load). Then **LOAD** (or double-click): it starts at once if nothing is loaded or planned, otherwise it joins TO DO; **UNLOAD** likewise. Loading and unloading several models can be planned this way.
2. **LENS**: the field shows the chosen lens (`AUTO` = best match). A click opens the full list: matches, lenses of the same shape (only valid for the same base model), others; `BROWSE .pt…` for a file, `TRAIN A LENS…` to train one. The choice is remembered per model.
3. Everything follows on: load split over the GPUs, unembed self-check, **workspace band** (WORKSPACE panel), **baseline profile** (12 prompts, the iris draws itself). The **HUD** at the top of the iris (in NERV style, on the PERSONA IRIS plate line, full width) shows the current step, its detail, the progress, the elapsed time and the queue.
   **TO DO** (left panel, TO DO button or Ctrl+J to hide it): everything that computes is planned there (applying levers with their coherence check, ALIGN, measures, PROFILE, CALIBRATE, REMAP, goal CHECK / ALIGN / TRAIN, EXPORT, chat replies, loads and unloads) and waits for **APPLY** (or Ctrl+Enter, from anywhere in the window, chat field included), which runs the list in order (**PAUSE** finishes the current operation then waits). With **AUTO** (button ringed when on), each operation starts as soon as it is added. Each row shows its state by color (○ waiting, ▶ running with its progress, ✓ done, ✗ failed with the error as tooltip, ⊘ stopped, ↻ replaced) and its ETA, learned from previous runs of the same model (≈ = first estimate, ~ = learned), plus the total time left. ✕ removes a waiting operation or stops the running one (Esc too; Shift+Esc stops and pauses the list); a waiting operation can be dragged up or down to reorder; **CANCEL ALL** (at the top, set apart) removes everything waiting, the running one goes on; **SHOW DONE** also shows finished operations (the last 60 are kept), off shows only what waits and what runs. Several successive settings merge into a single lever application (the latest). A lever application (or ALIGN, system prompt, active levers) that is stopped or fails keeps your sliders as set and goes back to waiting (‖): APPLY retries it, ✕ cancels it (the sliders then return to what is applied); even with AUTO, it waits for APPLY. The measure that follows a setting (*auto-measure*) is informative only: a chat message goes first, and a running measure is cut and restarted right after the reply. Saves (presets, ⚙ settings, goals, load options) never go through the list: they happen at once, even during a long TRAIN. With no model loaded, nothing is refused: LEVERS already shows the levers (without measures), and settings, ALIGN, PROFILE, CALIBRATE, JUDGE, presets, goal CHECK / ALIGN / TRAIN and messages join TO DO as usual; load a model before running them (without one, they fail). A click on the STATUS cell or on the job cell of the SYNC band shows the panel.
4. **Persona Iris**. Each radial axis is a trait; the rings are the layers, the orange ring the workspace band. The orange / violet clusters show where the trait activates layer by layer, the filaments and the polygon its value (grey = baseline, orange = current), and the floating words the model's own concepts. Drag to rotate, right-drag to pan (buttons configurable in ⚙ → NAVIGATION), wheel to zoom (toward the cursor once the view is panned, centered otherwise), ◎ (or C) to recenter, ⌖ (or Home) to reset everything; ⟳ (or R) stops / restarts the rotation, ◇ sets the concept labels (auto / all that fit, zooming reveals more / none), remembered; up to 200 concepts (⚙ → concept clouds, 120 by default; re-PROFILE for older profiles). Hovering a label (trait, concept, band mark) or a concept cloud: its card; click: pinned. The CONCEPTS panel at the bottom highlights concepts too. Click on a trait: detailed card pinned (poles, measure, layers, lever, readings, lexicon, concepts); "?" shows the help.
5. **LEVERS**: hovering a lever shows its card at once at the bottom left of the iris (poles, setting, applied strength, lever, reading, controls; or the measure on the right column). On the left *your setting* (−1.5 to +1.5 by default, adjustable: ⚙ → maximum lever dose): a click or a drag on the slider sets the value (0.05 steps); a click on the name selects the row without changing anything (brackets around the slider), dragging the name up or down moves the lever in the list (a goal keeps its └ LORA row; the order is kept, right-click → RESET THE LEVER ORDER); the wheel on the selected row's slider steps by 0.05, elsewhere it scrolls the list; double-click on the name or right-click → SET TO 0: 0. A setting joins TO DO (or starts at once with AUTO); a newer setting replaces the waiting one and, when the list runs, cuts the now obsolete coherence check, even in the middle of a generation. Lowering levers (or setting one to 0) from a mix that passed the check without correction does not rerun the judge. On the right *the measure* (▲ baseline, ● now), read only. A setting identical to the current one reruns nothing. The first setting of a trait extracts its lever (~10-40 s; or **CALIBRATE** for all), the slider pulses while it is applied. If the coherence guard lowers the strength, a red mark on the slider (and the line under it) shows the strength actually applied. **JUDGE** and its **AUTO** switch (on the DOSE / TARGET row, above the sliders; remembered): AUTO on, each setting goes through the guard (KL on a neutral text, then the judge on short replies); off, settings apply as set and nothing lowers them, until JUDGE (planned in TO DO; the number of levers not judged yet is shown on it), which only checks the levers changed since its last run: the others keep what was judged. Turning AUTO back on with levers not judged yet plans JUDGE. *auto-measure* then adds a quick measure (informative: the chat goes first).
   - **DOSE / TARGET** (switch above the sliders, remembered): in **DOSE**, each slider sets the strength of its lever. In **TARGET**, it sets the **wanted measured value**, on the same scale as MEASURED: ◆ the target, ● the current measure, the line between them turns green when the gap falls under 0.08, and ▸ the dose the alignment chose (red: the one the guard left; ▸+MAX in orange: at the ceiling). Only touched traits have a target, the others are free (their lever keeps its dose); double-click on the name or right-click → FREE to free a trait, TARGET ITS MEASURED VALUE to hold one where it is while the others move. Each change runs the **alignment**: the first time, a quick measure per lever (alone at +0.8) tells what it moves on every trait, interactions included (traits × levers matrix kept per model, remeasured if the lever, its calibration or the system prompt change); then the doses are solved on the displayed scale (least squares bounded by the maximum dose, ±1.5 by default, at most ±1 per round), applied (with JUDGE AUTO, under the KL guard only, the judge checking only the final doses, with one more measure if it lowers them; otherwise as they are), measured, and the matrix corrected by what was observed (damped Broyden, for the length of the alignment), up to 4 rounds. A target whose lever is already at the maximum leaves the solve so as not to degrade the others, and the best measured round is kept. Precision: about ±0.08, since the quick measure (6 generated replies) moves by as much from one dose to the next. The log tells which targets were reached, or why one is not (maximum dose, guard, lever without effect), and the TO DO row turns orange (!) with that verdict, including when there was nothing to change (lever already at the ceiling). Progress and ETA follow the real steps (preparation, rounds, final check). The SYNC waves then compare target and measure and come together as the gap closes. **ALIGN** reruns a few rounds, **ZERO** sets the doses back to 0 and removes every target (to keep the doses found, switch back to DOSE). Goals stay dosed by hand. Targets travel in presets (with the mode: loading a preset switches to its mode and, in TARGET, realigns the levers on its targets) and in the reply configuration.
6. **DIALOG** (adjustable width: handle between the iris and the dialog, remembered): talk to the modified model; **SEND** (Enter): if nothing waits in TO DO, the reply starts at once (no APPLY needed); otherwise the message queues after what is planned and starts with APPLY (or AUTO). It never goes ahead of settings (levers, system prompt, load…), only ahead of informative measures. Buttons in order HISTORY, CLEAR, STOP, REWIND, RETRY, SEND. **↶ REWIND** takes back the last message and its reply: the dialog goes back one exchange, so RETRY works again on the message before; the message comes back in the input (if it is empty) to edit or send again, its replies stay in the HISTORY. If the dialog exceeds the model's context, its oldest messages are left out for the reply (noted in the log). If a reply fails, the question stays: ↻ RETRY asks it again without retyping (a new message replaces it); **↻ RETRY** (Ctrl+R or F5, from anywhere in the window) regenerates the last reply and keeps the previous ones: ‹ 2/3 › on the reply switches between tries, and the one shown is the one the model keeps in memory from then on (the tries of an older reply stay in the history). You can thus chain several messages, settings and tries, come back later and choose. Each reply carries a **⟲ CONFIG** link: on hover, the configuration that produced it (levers set and applied, guard, goals, system prompt, sampling, seed); on click, RESTORE THIS CONFIGURATION puts it back, COPY AS TEXT copies it. **HISTORY** (Ctrl+H) lists every reply, RETRY tries and cleared dialogs included, with their message and configuration, filters by words, by model and without tries: restore or copy the configuration, copy the reply (`generations.jsonl` in the working folder). The live lens shows what each layer reads, token by token (can be turned off); it keeps the whole reply: widening the panel (handles between the bottom panels, widths remembered) or the wheel after a click (zoom) shows more tokens.
7. **+ LEVER**: create a lever from your own words (pole + / pole −). **ACTIVE LEVERS**: choose the levers taken into account (personality, custom levers, goals); the others are hidden from LEVERS and left out of every operation (dose 0, no alignment), their trait is still measured; the choice holds for every model and presets record it. **PRESETS**: save the high-level settings (lever settings as asked, before the guard; the DOSE / TARGET mode and its targets; the active levers; the goals they use with their sentences and questions; the system prompt; the levers that ignore the guard; the custom levers used, recreated if missing) in `presets/` of the working folder, then load them back: **APPLY** (or double-click) applies them at once, **PLAN IN TO DO** sets the sliders and the prompt and adds the changes to TO DO without running them (adjust, then APPLY in TO DO; ✕ on a change cancels it). Loading a preset switches to its mode: in TARGET the levers start from the saved doses and are realigned on its targets, in DOSE they are set as they are. **IMPORT A FILE…** also loads the `pendulum.json` of an export (in DOSE mode). A goal that already exists in another version is kept as it is (noted in the log). Rename or delete a preset: OPEN THE FOLDER.
8. **EXPORT**: writes `exports/<name>/` in the working folder with `<name>.cvec.gguf` (control vector; the name always starts with the model's architecture and size, for example `gemma4-E2B_sarcasm`, unless it already carries them; the size comes from the GGUF's `general.size_label`, else from the parameter count), `pendulum.json` (settings, profiles before / after), `run_llama_server.bat` and `lmstudio_override.txt` (LM Studio *llama.cpp override* block between triple backticks json, ready to copy; nothing is put in the clipboard: full paths written as `\\localhost\D$\…` because the strength follows a colon and the one of `D:` would cut the path); the folder icon next to EXPORT opens the exports folder.
9. **⚙** (Ctrl+,): folders, context, VRAM reserve (kept free on the GPUs that drive a screen, where Windows, the browser or a game grow; 256 MB on the others; detected through NVML), dialog sampling, lens repositories, iris frame rate, rotation (−360 to +360 °/s, negative = the other way), accent color.

## Identity goals (GOALS)
The **GOALS** window describes who the model should be: *who are you?*, *what do you want?*, *who am I to you?*, plus **custom questions** (facts the character knows: one question + expected answer row per fact, **+ QUESTION** to add one, X to remove it; **BULK…** opens an area to paste `question | expected answer` lines, to have an LLM write them in bulk, then **IMPORT** turns them into rows: list numbers and dashes ignored, `=>` or a tab work too, duplicates skipped, lines without a separator left in the area; ROWS → TEXT does the reverse).
- **TRAIN** (main button) trains the goal lever, with no other setting: the model, given the character as system prompt (the *twin*), answers about thirty questions (English and French paraphrases of the three questions, custom facts, everyday questions; never the check questions); with a judge, it gives three replies to the identity questions and the judge keeps the best two. A lever is then learned so that the model *without* the prompt answers like it, without moving a neutral text, then the judge checks the result. A trainable copy of the model is loaded in torch for the training (≈ 9 min in all for a 4B; the judge is unloaded, and the llama.cpp model set aside if VRAM runs short). When room is tight, the copy gets lighter: gradient checkpointing (activations recomputed, ≈ 30 % slower), then the first layers, those before the trained window, stay in RAM (they have no gradient: transfer only). Room is checked before the character answers, and its replies are kept: a new training of the same goal on the same model (same reply options, same judge) reuses them instead of redoing them. The goal lever shows up in LEVERS at +1: the slider doses it (0 = off). With the **vector + LoRA** carrier, it has two sliders: the goal's one doses the vector part, the **└ LORA** row right below the LoRA part (both at +1 after TRAIN, adjustable separately, exported as such).
  - **LoRA** carrier (default): small weights learned in the MLPs of the band (rank 8; the whole band by default), loaded live by llama.cpp; they only fire where the character matters. On Qwen3.5-4B HauhauCS, goal "Bubulle, a goldfish": 83 % by the judge (75 % on questions never seen), 90 % sense, exact name ("It's me, Bubulle! I'm a little golden fish living in my round bowl on the kitchen table"), neutral text intact (KL 0.001).
  - On "Bart, a grumpy old pirate captain": 61 % (62 % on questions never seen), against 2 % without the lever.
  - Custom facts: each custom question is rephrased by the model itself (in English) and reviewed more often during training. Bubulle + "What is the name of the cat? => Moustache": 86 % by the judge, the fact at 81 % ("It's Moustache! He has a very long, fluffy tail…").
  - **Vector** carrier: one direction per layer (control vector, read by any llama.cpp). With its current settings (step 0.01, drift on the neutral text bounded to KL 0.1 by a preservation that adjusts itself): 75 % on the goldfish; less precise than the LoRA and it moves the neutral text a little. If it does not learn, Pendulum says so.
  - **vector + LoRA**: worse than the LoRA alone in our tests (49 %).
  - Settings (optional): carrier, layers (band start, whole band, middle: by default the whole band for a LoRA, the band start for a vector, as long as you don't pick them yourself), steps, preservation (weight of the penalty that keeps the neutral text predicted as before: higher = the model stays itself outside the role but the goal takes less; for a vector it is the starting value, adjusted afterwards), replies kept per question, weights (bf16 or kept quantized, see Limits).
- **CHECK** asks the questions (in English) with the active levers; the judge first checks that the reply makes sense, then that it matches the target. **compare** option: each reply is also asked of the model without levers, and the judge says which fits best (VS BARE column, easier for a small judge). **PULL**: how much of the character prompt's pull the levers give, read without generating.
- **ALIGN** builds a goal lever (the character against the default assistant) and picks its dose from the judge (ALIGN BY: read + judge, read, or judge).
- A goal is only active where it was trained (TRAIN) or aligned (ALIGN): on another model its row says "not placed on this model · GOALS → TRAIN", its slider stays inactive and a dose that reaches it (preset, restored configuration) stays at 0. Right-click on a goal → **ADD AS A LEVER**: its character also becomes an ordinary lever (character ↔ default assistant, steerable but not measured by the lens), which reuses the direction already computed on this model and its dose; when a goal and a lever share a name, the rows are called NAME (goal) and NAME (lever).
- A learned lever is not subject to the coherence guard: its drift is measured during training, and the guard's surprise measure takes a change of character for incoherence.

## Coherence
Settings ⚙ → COHERENCE:
- **Recalibration**: each lever is set once on real short generations; strength 1 = as strong as possible while staying coherent (the old scale, set on a neutral text, quickly produced word salad).
- **Guard**: 2 short replies are generated and scored; if the mix derails, the levers are lowered (~3-10 s). When: on every change with JUDGE **AUTO** (DOSE / TARGET row of LEVERS), otherwise when you press **JUDGE**; unchecked (STANDBY), the levers apply exactly as set, at once: no judge, no KL guard, no factors kept from a previous judgment (they come back with a guard mode). **Maximum lever dose** (1.5 by default, up to 5): how far the sliders and ALIGN go; 1 = each lever's calibrated strength, the hatching starts beyond. The measured coherence shows in the header and the HUD.
- The TRACE, HISTORY, PRESETS and GOALS windows have their own title bar: drag the title plate to move, double-click or □ for full screen, ✕ to close, edges to resize.
- **TRACE** (button under RUN LOG, Ctrl+T, or click on a RUN LOG line marked ⌕: coherence check, calibration, judge self-test, goal check, alignment round, lever effects, which opens TRACE on that event): every judge test in detail, to tune tolerance, absurdity and judge knowingly: the context (lever change, guard step with its scale, calibration step), the test prompts, the modified model's replies, the probabilities the judge gives to the 4 levels (sensible, absurd, broken, salad) and the resulting score, the surprise; then the guard's decision (coherence at the asked strengths, reduction, result), the calibration results, the judge self-test (AUC per wording), the goal checks, and in TARGET what each lever moves alone and each alignment round (target, measure, asked and applied dose). Filters by type and by words; kept for the session (last 1500 events), SAVE… writes it as JSON.
- **Tolerance** (strict ↔ loose): required coherence threshold. **Absurdity** (sensible ↔ surreal): how much a grammatical but absurd text counts as coherent.
- **Guard mode**: *uniform* (every lever lowered together), *individual* (only the changed levers are judged, the one that hurts coherence most is lowered first), *quick* (fewer questions, falls back to individual) or *read* (the drop in log-probability of the bare model's replies, read without generating: low enough validates, high enough lowers by reading, in between falls back to the judge). **Individual calibration weight**: from 100 (each lever keeps its own calibration) to 0 (none, only the global guard sets the whole). **RECALIBRATE** (right-click on a lever, or for all) redoes the calibration, for example after changing the judge.
- **Judge** (optional): a second model, small and uncensored, scores each reply (1 sensible · 2 absurd · 3 broken · 4 salad) from its probabilities, without generating. Self-test at load (it must rank known examples perfectly, otherwise it is dropped); without a judge, the unmodified model's surprise measure is the fallback, and stays a safety net with a judge. Tested: huihui-qwen3-8b-abliterated and Qwen3.5-4B-Uncensored excellent, Gemma-4-E2B mixes up salad and absurd, the 1B ones are too lenient. Wordings tried at self-test: 1-4 scale (with or without examples), yes / no, A/B "decision" format (Jev-Style), or your own question; judge temperature, test prompts, test system prompt, length and number of replies adjustable.

## Levers, export, loading
- **Right-click on a lever**: edit, duplicate or delete a custom lever (optionally with the character played at each pole), recalibrate this one or all, **ignore the guard** for this lever (the judge is overridden: useful when it takes a wanted style, deadpan for example, for incoherence). The **default levers** can be edited too (EDIT…, RESTORE DEFAULT to go back to the original) and removed (REMOVE…, RESTORE A REMOVED LEVER to bring them back one by one); these choices live in `trait_overrides.json` of the working folder, `persona/traits.json` is never changed. When the lever set changes, the baseline profile is remeasured automatically.
- **EXPORT**: name, **global dose** (written in `run_llama_server.bat`: `--control-vector-scaled "name.cvec.gguf:dose"`, and `--lora-scaled "name.1.lora.gguf:strength"` for LoRA goals, editable afterwards), and for llama and mistral3 models the **GGUF copy with the levers built in** (exact: FFN output bias). Qwen3.5 and Gemma have no such bias in llama.cpp: the control vector stays the exact path, and the LoRA travels as a separate file.
- **Safetensors models**: MODELS also lists Hugging Face folders (`config.json` + tokenizer + `model*.safetensors`, HF cache included) and single `.safetensors` files that are language models (ComfyUI text encoders…). Since llama.cpp only reads GGUF, the first LOAD converts the model with the `convert_hf_to_gguf.py` of the llama.cpp folder (sources required), once: the GGUF is kept in `converted/` of the working folder, and MODELS then shows it instead of the source. ⚙ → *safetensors → GGUF*: lossless 16 bits (default) or Q8_0. A single file has neither config nor tokenizer: they come from the Hugging Face repository of the original model, guessed from the shapes (Qwen3 0.6B to 32B, Qwen3.5-4B, Qwen2.5-VL-7B, Llama 3.1 8B, Mistral Small 3.2, Gemma 2 2B) or given by right-click → *BASE MODEL…*. Weight names are mapped back to the repository's (`text_encoders.….model.` → `model.`), checked (names and shapes), and ComfyUI FP8 weights (`scale_weight`, `weight_scale` / `comfy_quant`) dequantized to BF16. NVFP4, MXFP8 and bitsandbytes files are refused. With no `lm_head` in the file while the original model has one, the embedding replaces it and a warning says so. Checked on Qwen3-0.6B: a renamed single file gives exactly the same GGUF as the HF folder (KL 0.0000).
- **LoRA export** (EXPORT → *LoRA (approximation)*): the active levers become a standard LoRA, without training. A lever adds a fixed vector to the activations whereas a LoRA changes weights: for each layer of the lever, a rank-1 LoRA on the MLP output weight (`ffn_down`) adds that vector, its input being fitted by least squares to be ≈ 1 over all activations (about 40 s). It is an approximation, measured on prompts never seen and written in `pendulum.json`: on Qwen3.5-4B, 92 % of the steering reproduced at the end of the network, 99 % of the prediction gap closed, identical replies at temperature 0. The LoRAs of trained goals (TRAIN) are merged into it. Files: `<name>.lora.gguf` (llama.cpp, koboldcpp, Ollama `ADAPTER`; the `.bat` loads it) and `.safetensors` with a choice of layer names: Hugging Face (`model.layers.N.mlp.down_proj`), PEFT folder, ComfyUI text encoder (`text_encoders.transformer.model.…`: LoraLoader with `strength_model` 0 and `strength_clip` to dose) or kohya (`lora_te_…`), editable prefix. Not for Gemma (normalized MLP output) nor MoE models. The LoRA only fits the model the levers were set on (for a ComfyUI text encoder: load that same model in Pendulum).
- **Load options**: defaults for every model in ⚙ → ENGINE (split over the GPUs: layers, rows or none; main GPU; flash attention; KV cache f16, q8_0, q4_0), and per model by right-click in MODELS → LOAD OPTIONS (take precedence). **LEVERS AT LOAD** (in MODELS): at load, take back the lever settings of the last time with this model, or keep the current ones (doses, targets, system prompt; goals not placed on the new model stay at 0). With "keep the current ones", the model's old settings are not restored at all, and the current ones are applied as soon as the model is loaded, even if its first profile is interrupted.
- **Working folder** (⚙): where profiles, exports, lenses, caches and settings go, instead of the project's `data` folder (applied at the next start, nothing is moved). The `PENDULUM_DATA_DIR` environment variable (or `--data-dir`) forces it for one run.
- **NERV style** (default, neon military terminal; ⚙ → DISPLAY → visual style: `nerv` or `plain`): neon plates and frames, condensed fonts, danger hatching beyond ±1, MAGI-like steps in the iris, accents `nerv`, `unit-01` (violet and green), `unit-02`, `unit-00` on top of the others.
- **SYNC band** (full width between top and bottom, height adjustable by dragging its edge; ⚙ can put it back as a small band in LEVERS): SYNCHRO RATIO in 7-segment digits, three waves *setting*, *applied* (after the guard) and *measured* that overlap when everything agrees, gap graph with counters, whose three columns merge into a single full-width graph as the wanted alignment is reached (in TARGET: when the measures reach the targets, within 0.08; in DOSE: when the three readings agree); it stirs during tasks, follows a goal's training (step, CE, KL), shows a hatched WARNING banner when the guard measures too low a coherence at the asked strengths (before → after its correction: "COHERENCE 41% < 65% · LEVERS ×0.50 → 72%") or still after, PATTERN BLUE when a placed goal fits, and a green READY banner when a job that changes the model ends (load, levers, calibration, profile, goal) with nothing waiting; the READY badge stays while nothing runs (⚙: WARNING and READY banners can be turned off). Click: switches the scenes shown; click on the job cell: JOBS panel. Tooltips depend on the hovered area (ratio, job, waves, graph, badges).
- **Sounds** (header speaker or Ctrl+Shift+M to mute / unmute; settings in ⚙ → SOUND): NERV-terminal-like beeps, alarms and chimes, all synthesized by Pendulum (numpy, nothing borrowed), played on the default Windows output (winmm, no dependency; no sound on Linux / macOS yet). Untested best guess, for Linux hosts (or Windows through WSL2 / WSLg) with an NVIDIA GPU and the [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).

```
xhost +local:docker
docker compose up --build
```

- The image builds llama.cpp with CUDA (`LLAMA_REF`, `CUDA_ARCHS`, `CUDA_VERSION` and `TORCH_INDEX` are build args) and installs PyTorch and the requirements in a venv.
- The window goes through X11: `/tmp/.X11-unix` and `DISPLAY` are passed in. Under WSLg this works as is; elsewhere `xhost +local:docker` lets the container draw.
- Volumes: `./data` = the working folder (`/data`), `HF_CACHE` (default `~/.cache/huggingface`) = the Hugging Face cache (`/hf`), `MODELS` (default `./models`) = your GGUF folder (`/models`, add it in the setup assistant). Example: `MODELS=/mnt/llm HF_CACHE=/mnt/hf docker compose up`.
- llama.cpp sits in `/opt/llama.cpp` (`PENDULUM_LLAMA`), sources included, so safetensors conversion works too.
- No sound in the container (sound output is Windows only for now), and the end-of-list shutdown is off.

## Training a lens
`TRAIN A LENS…` (in the LENS window) runs Anthropic's `jlens.fit` in a subprocess: from the GGUF itself (dequantized by transformers, for the architectures it knows: llama, qwen2/3, gemma2/3/4, mistral…) or from the Hugging Face weights of the base model (required for Qwen3.5). WikiText, 100 prompts by default, bf16 or nf4, one or two GPUs, every layer or the workspace band only (faster, smaller). Count hours (≈ 40 s per prompt for a 1B on an RTX 4070; the estimate is shown). Can be stopped: checkpoints are kept and `START` with the same name resumes. The lens lands in `lenses/<name>/` of the working folder and is picked automatically for its model.

Using the export elsewhere:
```
llama-server -m model.gguf --control-vector name.cvec.gguf
```

## What is measured
- **Workspace band**: autocorrelation of the lens top-1 (persistent abstract content, compared to a shuffled order) up to the entry of the motor regime (the lens joins the real output, top-5 agreement ≥ 0.8).
- **Profile**: log-odds (pole + vs pole −) of each trait's vocabulary in the lens readings, while speaking, compared to the reading of a neutral text. Each trait's lexicon is specific to the model: seeds, then single-token variants, then neighbors in W_U. Profile modes: WRITE (generated replies), READ (prewritten replies read, ≈ 6× faster, 0.98 correlation with writing) or READ + WRITE (default: reading, scaled per lever by one written probe).
- **Levers**: *persona* directions (the model plays pole + then pole −, mean of the residual), placed in the first part of the workspace, where the disposition lives rather than the word. Calibrated on short generations, and interpreted by the lens ("reads as").

## Limits
- Without a Jacobian lens, the logit lens reads the middle of the network poorly: profile, band and "reads as" are noisier, but the levers still work. Hence lens training.
- The control vector is an additive term per layer, faithful across the llama.cpp ecosystem. Exact baking into the weights only exists for llama and mistral3 (FFN bias); elsewhere, goals go through a LoRA adapter (loaded by llama.cpp and llama-server, not merged into the GGUF).
- The Jacobian lens is an average: in the band, its direction only matches the true gradient of a given context at cos 0.12-0.5 (measured on Qwen3.5-4B). It is a map, not a compass: TRAIN aims with the true gradient.
- TRAIN needs a torch copy of the model: Qwen3.5 (exact loader), Gemma 4 (configuration read from the GGUF, checked on E2B and E4B; the large per-layer embedding table stays in RAM and is read on the CPU) and the architectures transformers can read from GGUF (llama, mistral, qwen2/3, gemma2/3…), in bf16 (≈ 2 bytes of VRAM per parameter, split over the GPUs) or, when that does not fit, with the frozen weights kept quantized as in the GGUF (WEIGHTS setting; *auto* takes the fastest that fits): each matrix is unpacked chunk by chunk on the fly, including those the loader reorders (Qwen3.5 *linear attention* layers, llama q/k), the embedding and the head too. Example: Qwen3.8-27B IQ4_XS, 14.3 GB of weights, trains on 16 + 12 GB (loaded in 26 s, ≈ 33 s per step with gradient checkpointing; 40 steps: 89 % of the gap to the character closed, KL 0.003). Elsewhere, ALIGN stays available; MoE models cannot be trained yet.
- MoE: loading and levers work (experts on CPU if needed), but the slightest CPU spill is costly.
