# HypnoLens — code map

Établi de personnalité pour LLM GGUF : cartographie du workspace par la lentille jacobienne, profil de personnalité, leviers (control vectors), export. Application de bureau PySide6, moteur llama.cpp en `ctypes`.

## Arborescence

|---|---|
| `README.md`, `docs/` | README court (bannière `docs/banner.svg` faite à la main, capture `docs/screenshot.png` de la session de test, quatre colonnes MESURER / RÉGLER / INCARNER / EXPORTER, démarrage, principe, chiffres) ; tout le détail dans `docs/GUIDE.md` (l'ancien README, complété) |
| `HypnoLens.pyw` | Entrée GUI (identifiant d'application Windows `Pendulum.Workbench` pour l'icône de la barre des tâches). ## Flux
1. **Chargement** : plan (`gpus.plan_load`), puis `Engine.load`, lens, `Readout`, auto-contrôle, lexiques, scorer, restauration de l'état sauvé.
2. **Bande** : `workspace.analyze` sur 8 textes neutres, puis `detect_band`.
3. **Profil** : réponses de la batterie capturées sur toutes les couches, log-odds pôle+/pôle− lus par la lentille, delta vs référence neutre. Donne le radar (`tanh(delta/2,5)`), la matrice trait × couche (iris) et les concepts qui montent.
4. **Levier** : paires de prompts système pôle+/pôle− → moyenne du résidu en parlant → direction par couche. On garde la fenêtre de 7 couches à séparation maximale dans les 65 % premiers de la bande, puis gain calibré (KL 0,45 sur texte neutre).
5. **Application** : somme des leviers, garde-fou (KL ≤ 1,8), puis `llama_set_adapter_cvec`.
6. **Chat** : génération steered, `frame()` à chaque token (odds par couche, top-3 de la lentille), iris et heatmap en direct.

## Invariants & pièges
- **Nombre de couches** : `n_layer = llama_model_n_layer`, qui exclut déjà les couches MTP/nextn. Ne pas soustraire `n_layer_nextn`.
- **Norme finale GGUF** : γ déjà décalé par le convertisseur (Qwen3.5/Gemma). Vérifié par `selfcheck` (cos 0,99996–1,0).
- **`cb_eval`** : appelé pour chaque nœud du graphe. Retour immédiat quand aucune couche n'est demandée. Les frames coûtent ~5 ms/token (4B).
- **OpenMP** : torch charge `libiomp5md`, ggml charge `libomp`, d'où `KMP_DUPLICATE_LIB_OK=TRUE` dans `setup_env`.
- **Variables d'env depuis Git Bash vers cmd** : passer par un `.bat`, les guillemets sont échappés sinon.
- **Lentille** : les J de Neuronpedia (fittées sur HF) s'appliquent directement au résidu llama.cpp (même base). Finetunes : lens du modèle de base.
- **Leviers** : les directions J-lens de *mots* font *nommer* (« cold ice cold… »). Les leviers utilisent des directions persona, la lentille sert de carte et d'interprétation (« se lit comme »).
- **Persistance** : écriture atomique (tmp puis `os.replace`) ; `np.load` dans un `with` (verrou Windows). `levers.VERSION` invalide les leviers sauvés quand l'algorithme change.
- **UI** : les payloads d'événements sont partagés avec le thread moteur, d'où un `deepcopy` à la réception.
- **Barres de titre** : `DarkFrames` (window.py) force la barre de titre native en sombre (DWM attribut 20) sur toute fenêtre à cadre, avant affichage.
- **Pas de surface OpenGL dans la fenêtre** : un `QOpenGLWidget` passait toute la fenêtre en surface GL, que le pilote pouvait promouvoir en « plein écran direct » (image étirée, PrintScreen/OBS faux ou noirs). L'iris est rendue hors écran puis dessinée en raster.
- **GIL** : UI et moteur partagent l'interpréteur (callbacks `cb_eval` en Python). Tout travail Python lourd dans l'UI ralentit la génération : `sys.setswitchinterval(0.001)`, libellés de l'iris en cache, lentille live incrémentale, iris à 30 fps quand le moteur travaille.
- **Fiche levier** : `LeverTable.peek_card` construit le contenu (valeurs en direct, même pendant un glisser) ; l’iris ne fait que l’afficher (`set_peek`), sans décaler la vue. Pas d’infobulles sur les leviers (elles couvraient les curseurs).
- **Boutons et focus** : `button()` = `TabFocus` + `autoDefault` désactivé : un clic ne donne pas le focus, donc plus de cadre pointillé « texte sélectionné » ; le cadre natif n'apparaît qu'après une navigation au clavier (Tab). Entrée déclenche le bouton par défaut explicite (SAVE, CREATE, USE SELECTED), Échap annule. Pas de style `:focus` sur les boutons : le focus initial (premier bouton de la chaîne) les ferait paraître sélectionnés.
- **Délai des infobulles** : `QStyleHints` n'en a pas ; `TipStyle` (proxy du style natif, posé avant la feuille de style) ne surcharge que `styleHint`, pour garder Python hors des chemins de dessin.
- **Dossier de travail** : lu une seule fois à l'import de `config` ; avec `HYPNOLENS_DATA_DIR` (tests) `workdir.json` n'est ni lu ni écrit. Un changement s'applique au redémarrage ; les données existantes ne sont jamais déplacées.
- **Leviers** : les curseurs portent l'intention de l'utilisateur (`strengths`), jamais réécrite par les événements ; l'état appliqué (`applied`) sert à l'info et à la réconciliation (retour à l'appliqué si un changement est interrompu).
- **Lentilles** : « même forme » ne veut pas dire « valide » (Qwen3-14B a la forme des Mistral 12B) ; seules les correspondances de nom sont prises automatiquement.
- **Options llama-server** : `--control-vector-scaled` et `--lora-scaled` prennent `FICHIER:FORCE` (un seul argument, découpé sur `:`) : un chemin Windows absolu (`D:`) casse le découpage, d'où le `cd /d "%~dp0"` et les noms relatifs dans le `.bat`.
- **LoRA et pilotage** : les adaptateurs sont posés sur le contexte (pas par appel) ; tout passe par `Engine.set_steering(dict)` avec la clé `LORA`, pour que les mesures « modèle nu » (`set_steering(None)`) coupent aussi les LoRA. Réentraîner un but réécrit le même fichier : `drop_lora` oublie l'ancien adaptateur (libéré avec le modèle).
- **Débordement CPU** : l'i7-6700K coûte −80 %. Le planificateur privilégie le 100 % GPU (réduit le contexte, puis déplace la lentille avant le modèle). « Host » dans les estimations = embeddings d'entrée, normal.
