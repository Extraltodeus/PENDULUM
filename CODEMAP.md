# Pendulum — code map

Personality workbench for GGUF LLMs: workspace mapping through the Jacobian lens, personality profile, levers (control vectors), export. PySide6 desktop application, llama.cpp engine through `ctypes`.

## Flow
1. **Load**: plan (`gpus.plan_load`), then `Engine.load`, lens, `Readout`, self-check, lexicons, scorer, saved state restored.
2. **Band**: `workspace.analyze` on 8 neutral texts, then `detect_band`.
3. **Profile**: replies of the battery captured on every layer, pole+/pole− log-odds read by the lens, delta vs neutral reference. Gives the radar (`tanh(delta/2.5)`), the trait × layer matrix (iris) and the rising concepts.
4. **Lever**: pairs of pole+/pole− system prompts → mean residual while speaking → direction per layer. The 7-layer window with maximal separation within the first 65 % of the band is kept, then a calibrated gain (on short generations; KL on neutral text as a first step).
5. **Application**: sum of the levers, guard (KL, then the judge per the guard mode), then `llama_set_adapter_cvec`.
6. **Chat**: steered generation, `frame()` at each token (odds per layer, lens top-3), live iris and heatmap.

## Invariants & pitfalls
- **Layer count**: `n_layer = llama_model_n_layer`, which already excludes MTP/nextn layers. Do not subtract `n_layer_nextn`.
- **GGUF final norm**: γ already shifted by the converter (Qwen3.5/Gemma). Checked by `selfcheck` (cos 0.99996–1.0).
- **`cb_eval`**: called for every graph node. Returns at once when no layer is requested. Frames cost ~5 ms/token (4B).
- **OpenMP**: torch loads `libiomp5md`, ggml loads `libomp`, hence `KMP_DUPLICATE_LIB_OK=TRUE` in `setup_env`.
- **Env variables from Git Bash to cmd**: go through a `.bat`, quotes get escaped otherwise.
- **Lens**: Neuronpedia J's (fitted on HF) apply directly to the llama.cpp residual (same basis). Finetunes: the base model's lens.
- **Levers**: J-lens *word* directions make the model *name* ("cold ice cold…"). Levers use persona directions, the lens serves as map and interpretation ("reads as").
- **Persistence**: atomic writes (tmp then `os.replace`); `np.load` inside a `with` (Windows lock). `levers.VERSION` invalidates saved levers when the algorithm changes.
- **UI**: event payloads are shared with the engine thread, hence a `deepcopy` on reception.
- **Title bars**: `DarkFrames` (window.py) forces the native title bar dark (DWM attribute 20) on every framed window, before showing.
- **No OpenGL surface in the window**: a `QOpenGLWidget` turned the whole window into a GL surface, which the driver could promote to "direct full screen" (stretched image, wrong or black PrintScreen/OBS). The iris is rendered off screen then drawn as raster.
- **GIL**: UI and engine share the interpreter (`cb_eval` callbacks in Python). Any heavy Python work in the UI slows generation: `sys.setswitchinterval(0.001)`, cached iris labels, incremental live lens, iris at 30 fps while the engine works.
- **Lever card**: `LeverTable.peek_card` builds the content (live values, even during a drag); the iris only shows it (`set_peek`), without shifting the view. No tooltips on the levers (they covered the sliders).
- **Buttons and focus**: `button()` = `TabFocus` + `autoDefault` off: a click does not give focus, so no dotted "selected text" frame; the native frame only shows after keyboard navigation (Tab). Enter triggers the explicit default button (SAVE, CREATE, USE SELECTED), Esc cancels. No `:focus` style on buttons: the initial focus (first button of the chain) would make them look selected.
- **Tooltip delay**: `QStyleHints` has none; `TipStyle` (proxy of the native style, set before the style sheet) only overrides `styleHint`, to keep Python out of the drawing paths.
- **Working folder**: read once when `config` is imported; with `PENDULUM_DATA_DIR` (tests) `workdir.json` is neither read nor written. A change applies at restart; existing data is never moved.
- **Levers**: the sliders carry the user's intent (`strengths`), never rewritten by events; the applied state (`applied`) is for information and reconciliation (back to the applied state if a change is interrupted).
- **Lenses**: "same shape" does not mean "valid" (Qwen3-14B has the shape of the Mistral 12B ones); only name matches are picked automatically.
- **llama-server options**: `--control-vector-scaled` and `--lora-scaled` take `FILE:STRENGTH` (a single argument, split on `:`): an absolute Windows path (`D:`) breaks the split, hence the `cd /d "%~dp0"` and the relative names in the `.bat`.
- **LoRA and steering**: adapters are set on the context (not per call); everything goes through `Engine.set_steering(dict)` with the `LORA` key, so that "bare model" measures (`set_steering(None)`) also cut the LoRAs. Retraining a goal rewrites the same file: `drop_lora` forgets the old adapter (freed with the model).
- **CPU spill**: costs −80 % (measured on an i7-6700K). The planner favors 100 % GPU (lowers the context, then moves the lens before the model). "Host" in the estimates = input embeddings, normal.
